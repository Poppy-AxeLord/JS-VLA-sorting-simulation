# 指标体系文档 —— 工业分拣 VLA 评测

> 文档定位：本文详解项目的指标体系（对应 `config/metrics.yaml` 与 `src/evaluation/metrics.py`）。核心命题是：**一个好的指标体系，不是把所有能算的数都堆出来，而是用分层结构让每个指标都能回答一个具体的产品/工程问题，并直接驱动下一步决策。**

---

## 一、为什么要"分层 + 四组"两个维度并存

工业分拣的评测如果只有"成功率"一个数，会陷入两个陷阱：

1. **只见结果，不见过程。** 成功率从 0.74 涨到 0.83，是因为感知变好了、还是执行变稳了、还是只是这批任务恰好简单？单一指标无法归因。
2. **效果好不代表能落地。** 一个成功率 0.9 但平均耗时 30 秒、人工介入率 40% 的系统，在产线上毫无价值。

所以我们用**两个正交维度**组织指标：

- **分层维度（回答"谁该看"）**：北极星 → 核心 → 过程 → 辅助。层级越高越靠近商业价值，越低越靠近工程细节。决策者看北极星和核心，工程师看过程和辅助。
- **功能四组维度（回答"看什么方面"）**：效果 / 效率 / 稳定性 / 成本。任何一个能落地的系统，这四个方面缺一不可。

两个维度交叉，形成一张完整的"评测地图"，确保我们既不漏掉关键视角，也不会被无关指标淹没。

---

## 二、分层结构总览

```
北极星指标（1 个）——————— 任务成功率
   │  唯一最高目标，所有迭代最终都要回答"它涨了没有"
   ▼
核心指标（效果组）————————— 分拣准确率 / 误拣率 / 漏拣率
   │  拆解北极星，回答"成功率背后效果质量如何"
   ▼
过程指标（效率 + 稳定性）—— 耗时 / 吞吐 / 抓取成功率 / 识别准确率 / 碰撞 / 恢复
   │  回答"为什么效果是这样、瓶颈在哪个环节"
   ▼
辅助指标（成本组）————————— 平均重试次数 / 人工介入率
      回答"达成这个效果的代价有多大、能不能规模化"
```

## 三、逐指标详解

下表每个指标都给出：英文 key（与 `metrics.py` 返回 dict 一致）、定义口径、目标值、以及**最关键的"如何驱动迭代"**。

### 北极星指标

| 指标 | key | 口径定义 | 目标 | 如何驱动迭代 |
|---|---|---|---|---|
| 任务成功率 | `task_success_rate` | 成功任务数 / 总任务数。一个任务"成功"= 该任务所有目标零件都被正确分拣到位且无致命失败 | ≥ 0.80 | 这是唯一的"涨没涨"裁决标准。任何优化先看它，再看是哪一层指标带动了它。v1→v2→v3 的 0.62→0.74→0.83 就是用它串起整个迭代叙事 |

> 产品决策：为什么北极星是"任务成功率"而不是"零件准确率"？因为工业场景里**任务是交付单位**——"把这盘料分拣完"才有价值，分对 90% 的零件但漏了关键的那个芯片，整个任务对产线就是失败的。北极星必须对齐真实交付单位。

### 核心指标（效果组）

| 指标 | key | 口径定义 | 目标 | 如何驱动迭代 |
|---|---|---|---|---|
| 分拣准确率 | `sort_accuracy` | 正确分拣零件数 / 目标零件总数 | ≥ 0.90 | 比成功率更细的效果度量。若成功率低但准确率不低，说明失败集中在少数零件（往往是易碎件/相似件），优化方向是"啃硬骨头"而非"全面提升" |
| 误拣率 | `mis_pick_rate` | 错拣数 / 已拣数 | ≤ 0.05 | 误拣直接对应"理解类/感知类失败"。误拣率高 → 去看失败分析里的"识别错误/指令理解错误"占比，针对性优化解析或感知 |
| 漏拣率 | `miss_pick_rate` | 漏拣数 / 目标零件总数 | ≤ 0.08 | 漏拣往往来自遮挡（感知）或规划顺序（漏处理）。漏拣率高 → 优先排查"遮挡看不见""分拣顺序错误" |

> 误拣 vs 漏拣的产品意义不同：**误拣是"做错了"（零件流向错误工序，隐性成本高），漏拣是"没做"（零件留在原地，可补救）。** 在 3C 场景误拣代价通常更高，所以误拣率目标比漏拣率更严。

### 过程指标 —— 效率组

| 指标 | key | 口径定义 | 目标 | 如何驱动迭代 |
|---|---|---|---|---|
| 平均任务耗时 | `avg_task_ms` | 所有任务耗时(ms)的平均 | ≤ 8000 ms | 反映端到端速度。耗时突增要拆到单步耗时和重试次数找根因 |
| 平均单步耗时 | `avg_step_ms` | 所有 action 步耗时(ms)的平均 | ≤ 600 ms | 定位是哪个环节慢（感知/规划/执行）。是优化算力分配的依据 |
| 单位时间分拣数 | `throughput_per_min` | 成功分拣件数 / 总耗时（折算每分钟） | ≥ 8 件/分钟 | 直接对应产线节拍。决策者最关心的"产能"指标，和成本一起算 ROI |

### 过程指标 —— 稳定性组

| 指标 | key | 口径定义 | 目标 | 如何驱动迭代 |
|---|---|---|---|---|
| 抓取成功率 | `grasp_success_rate` | 抓取成功次数 / 抓取尝试次数 | ≥ 0.90 | 直接对应"执行类失败-抓取失败(滑落)"。低 → 优化夹爪策略/抓取姿态/世界模型风险预判 |
| 识别准确率 | `recognition_accuracy` | 识别正确零件数 / 识别尝试数 | ≥ 0.92 | 直接对应"感知类失败"。低 → 多视角融合、光照增强是首选方向 |
| 碰撞次数 | `collision_count` | 一次评测中发生碰撞的总次数 | 越低越好（趋 0） | 对应"执行类-碰撞导致失败"。高 → 优化路径规划（planner 的避障/顺序） |
| 异常恢复率 | `recovery_rate` | 成功恢复的异常数 / 发生的异常数 | ≥ 0.50 | 衡量系统鲁棒性。高恢复率意味着失败可自愈、人工介入少，是"可落地"的关键稳定性信号 |

### 辅助指标（成本组）

| 指标 | key | 口径定义 | 目标 | 如何驱动迭代 |
|---|---|---|---|---|
| 平均重试次数 | `avg_retry` | 总重试次数 / 任务数 | ≤ 0.8 | 重试多 = 隐性算力/时间成本高。重试集中在哪类零件，就去优化哪类的执行策略 |
| 人工介入率 | `human_intervention_rate` | 需要人工介入的任务数 / 总任务数 | ≤ 0.10 | 直接对应人力成本和"信任边界"。这是 ROI 测算的关键变量——介入率越低，自动化价值越高 |

## 四、雷达图：把多指标压成一张可对比的"体检图"

`config/metrics.yaml` 为每个指标定义了 `radar_weight`，用于在看板"版本对比页"绘制雷达图。雷达图选取 6 个归一化维度：**成功率 / 准确率 / 速度 / 稳定性 / 低成本 / 恢复率**。

- 归一化方法：每个维度按"目标值"或合理上下界做 0~1 缩放，越外圈越好（成本和耗时类做反向归一化，即"越低成本→雷达值越高"）。
- 产品价值：决策者一眼就能看出"v2 比 v1 全面外扩，但 v3 在速度维度略有牺牲换取了稳定性大幅提升"——这种**多维 trade-off 的可视化，是单一成功率永远给不出的洞察**。

## 五、指标如何支撑决策（三个真实决策场景）

指标体系的终极考验是"能不能帮人做决定"。举三个本项目里真实会发生的决策：

### 决策场景 1：v2 该不该上世界模型（要不要做 v3）
- **看什么**：v2 的过程指标显示 `grasp_success_rate` 在易碎大件上偏低，`mis_pick_rate` 在困难难度偏高。
- **推理**：失败集中在"抓取滑落"和"遮挡识别"，而世界模型恰好能在抓取前预判风险。
- **决策**：上 world_model。**结果验证**：v3 成功率 0.74→0.83，稳定性组指标全面改善，决策正确。

### 决策场景 2：下一步优化感知还是理解
- **看什么**：失败分析的 `category_distribution`，对照核心指标的误拣率/漏拣率。
- **推理**：若感知类失败占比最高且漏拣率高 → 优化感知（多视角融合）；若理解类失败高且误拣率高 → 优化指令解析。
- **决策**：用数据而非直觉选方向。这正是 `iteration_plan.md` 里 v4/v5 排序的依据。

### 决策场景 3：能不能给决策者承诺一个 ROI
- **看什么**：`throughput_per_min`（产能）+ `human_intervention_rate`（人力成本）+ `avg_retry`（隐性成本）。
- **推理**：产能 × 良率 − 人工兜底成本 = 单位时间净价值。
- **决策**：成本组指标接入真实成本系数后，就能输出"vs 传统方案省多少钱"的 ROI 结论。这是说服 CFO 的最后一公里。

## 六、指标体系的设计原则总结

1. **每个指标都要能回答一个具体问题、驱动一个具体动作。** 不能驱动决策的指标一律不进体系（避免"虚荣指标"）。
2. **分层让信息分流。** 决策者不被工程细节淹没，工程师能下钻到根因。
3. **四组保证落地完整性。** 效果好 + 效率高 + 稳定 + 成本低，四者俱全才叫"能用"，缺一不可。
4. **指标与失败分类强绑定。** 几乎每个过程/核心指标都能映射到某一类失败（见各行"如何驱动迭代"），这让"指标异常 → 失败归因 → 优化动作"形成闭环，详见 `failure_analysis.md`。
5. **可复现可对比。** 所有指标由 `metrics.py` 从 `TaskResult` 确定性计算，benchmark 支持 seed，保证版本间对比公平可信。

> 一句话：**这套指标体系的真正产出不是一堆数字，而是一条"看哪个指标 → 得什么结论 → 做什么动作 → 验证涨了没"的决策流水线。**
