# 产品设计文档 —— 工业分拣 VLA 仿真 POC

> 文档定位：本文从产品经理（PM）视角，回答"我们到底在做一个什么产品、为谁做、解决什么问题、离真正落地还差什么"。配套技术契约见 `SPEC2.md`，本文不重复技术细节，只讲产品决策逻辑。

---

## 一、产品定位：这是一次"产品验证"，不是一个"算法 Demo"

行业里 VLA（Vision-Language-Action，视觉-语言-动作大模型）类项目最常见的失败姿势是：堆一个炫酷的抓取视频，跑分刷一个 SOTA，然后在落地评审会上被一句话问倒——"它在我的产线上能用吗？故障了怎么办？谁来背锅？"。

本项目刻意反其道而行。我们交付的核心**不是一个"能抓起螺丝"的算法**，而是一套**回答"VLA 分拣能否在工业 3C 场景落地"这个商业问题的产品验证系统**。

| 维度 | 算法 Demo（我们刻意不做的） | 产品验证（我们交付的） |
|---|---|---|
| 核心交付物 | 一段抓取成功的视频 / 一个跑分 | 一套可复现的评测体系 + 失败归因 + 迭代决策链路 |
| 关心的问题 | "成功率能到多少？" | "失败时是哪一类失败？怎么修？修了能涨多少？" |
| 衡量标准 | 单一准确率 | 北极星 + 核心 + 过程 + 辅助 四层指标 |
| 对失败的态度 | 失败不展示、调参数刷上去 | 失败是一等公民，5 大类归因，驱动迭代 |
| 给老板看什么 | "看，它动了！" | "v1→v2→v3 成功率 0.62→0.74→0.83，下一步投 X 预计再涨 6~8pct" |

一句话总结产品定位：**用最低的工程成本（纯核心依赖即可全演示），把"VLA 工业分拣"这件事从'技术上能不能做'推进到'产品上值不值得做、该怎么做'的决策门口。**

这个定位决定了几个关键的产品取舍：

1. **容错降级是第一原则，而不是性能。** 我们宁可让仿真退化为 MockPhysics、让 VLA 退化为规则基线，也要保证**任何一台 Mac 只装核心依赖（numpy/pandas/pyyaml/streamlit/plotly/matplotlib）就能完整跑通**。因为产品验证的受众是决策者，他们要的是"我现在就能看到结论"，而不是"先帮我配三天 CUDA 环境"。
2. **失败注入是有意为之的产品设计，不是偷懒。** 我们用概率模型注入 5 类失败（详见 `failure_analysis.md`），目的是让评测和失败分析**真实可分析**——决策者需要看到"失败长什么样、怎么分布、能不能修"，而不是一个永远 100% 的假成功率。
3. **看板开箱即丰富。** 预置 3 个版本的演示数据（v1/v2/v3），让任何人打开就能看到趋势、对比、失败归因，无需先跑半小时评测。这是"产品"和"脚本"的根本区别。

## 二、目标用户与角色

VLA 工业分拣不是单点工具，它的价值在一条决策链上流动。我们识别出四类核心角色，产品的每个模块都对应着某个角色的关键决策：

### 角色一：产线/自动化决策者（买单的人）
- **画像**：3C 制造工厂的自动化负责人、智能制造部门总监。手里有预算，但被太多"AI 落地"概念伤过。
- **核心诉求**：这套方案在我的产线上**值不值得投入**？投入后**良率/效率能提升多少**？故障率我能不能接受？
- **产品如何服务**：看板"总览页"的北极星指标（任务成功率）+ 按难度/类型的表现对比，以及"版本对比页"的提升趋势和 ROI 式的优化建议（"投入 X，预期收益 +Y pct"）。

### 角色二：算法/AI 工程师（迭代的人）
- **画像**：负责把 VLA 模型调到能用的工程师。
- **核心诉求**：现在卡在哪？是感知不行、理解不行还是执行不行？**下一步该优化什么投入产出比最高**？
- **产品如何服务**："失败分析页"的 5 类失败分布、Top10 子类排行、失败案例（含合成场景图），以及 `recommendation.py` 生成的可执行优化建议。

### 角色三：现场操作/质量工程师（用的人 + 兜底的人）
- **画像**：产线上真正盯着分拣的人，VLA 失败时需要人工介入。
- **核心诉求**：什么时候需要我介入？系统能不能自己恢复？哪些零件最容易出问题？
- **产品如何服务**：过程指标里的"人工介入率""异常恢复率"，以及按零件属性的失败聚合（易碎大件放置失败率高等）。

### 角色四：产品经理 / 项目负责人（规划的人）
- **画像**：我自己。要向上汇报、向下排期、对外讲故事。
- **核心诉求**：怎么把"技术进展"翻译成"产品进展和商业价值"？路线图怎么排？
- **产品如何服务**：整套分层指标体系 + 失败驱动迭代的方法论 + `iteration_plan.md` 的路线图。

> 产品决策记录：我们没有为"工人直接操作"设计交互界面，因为本阶段是**产品验证**而非**产线部署**。验证阶段的真正用户是"决策者 + 工程师"，他们消费的是"结论和归因"，不是"实时控制"。这是一个刻意的范围收敛。

## 三、核心场景：工业 3C 零件分拣

我们锁定 **3C（计算机/通信/消费电子）制造的来料/成品零件分拣** 作为核心场景，原因有三：

1. **零件多样性天然适配 VLA 的"视觉-语言"优势。** 3C 零件在材质（金属/塑料/陶瓷/玻璃/复合）、颜色、大小、形状、易碎性上差异巨大（见下表 10 种权威零件），传统视觉 + 固定夹具的方案需要为每种零件做工程，而 VLA 的卖点正是"用自然语言指令就能泛化处理新零件"。
2. **指令复杂度可分级，能系统性压测 VLA 的语言理解。** 我们把分拣指令设计为 5 种类型，从易到难覆盖了 VLA 落地最关心的"指令理解边界"：

| 指令类型 | 示例 | 考察能力 |
|---|---|---|
| 基础分拣 | "把红色的螺丝放到 A 区" | 单属性识别 + 定位 |
| 条件分拣 | "把所有金属零件分拣到 B 区" | 属性归类 + 批量约束 |
| 优先级分拣 | "优先分拣芯片，然后是电容" | 顺序/优先级规划 |
| 批量分拣 | "把所有零件按颜色分类" | 多类别同时决策 |
| 模糊分拣 | "把大的零件放左边，小的放右边" | 模糊语义 + 相对约束 |

3. **失败有明确的工业代价，归因有商业价值。** 易碎件（芯片/PCB/显示屏）放置失败 = 直接报废损失；误拣 = 流向错误工序的隐性成本。这让"失败分类"从学术概念变成了真金白银的决策依据。

**权威零件库（10 种 3C 零件）：**

| code | 中文名 | 材质 | 颜色 | 大小 | 形状 | 易碎 |
|---|---|---|---|---|---|---|
| screw | 螺丝 | 金属 | 银色 | 小 | 圆柱 | 否 |
| nut | 螺母 | 金属 | 银色 | 小 | 六边形 | 否 |
| capacitor | 电容 | 金属 | 蓝色 | 小 | 圆柱 | 否 |
| resistor | 电阻 | 陶瓷 | 棕色 | 小 | 圆柱 | 否 |
| chip | 芯片 | 塑料 | 黑色 | 中 | 方形 | 是 |
| connector | 连接器 | 塑料 | 白色 | 中 | 方形 | 否 |
| heatsink | 散热器 | 金属 | 银色 | 大 | 块状 | 否 |
| pcb | PCB板 | 复合 | 绿色 | 大 | 平板 | 是 |
| button | 按键 | 塑料 | 红色 | 小 | 方形 | 否 |
| display | 显示屏 | 玻璃 | 黑色 | 大 | 平板 | 是 |

分拣到 3 个料盒区：`A区` / `B区` / `C区`。难度三档（简单 3 件无遮挡 / 中等 5 件含相似物 / 困难 8 件含遮挡），让评测覆盖从"理想环境"到"真实产线噪声"的连续谱。

## 四、功能架构

产品按"输入指令 → 理解决策 → 仿真执行 → 评测归因 → 决策迭代"的价值链分层，每一层都对应技术契约里的一个模块组：

```
┌─────────────────────────────────────────────────────────────┐
│  决策层（看板 Dashboard）                                      │
│  总览 / 失败分析 / 版本对比  ——  给决策者和 PM 看结论          │
├─────────────────────────────────────────────────────────────┤
│  评测层（Evaluation）                                          │
│  metrics 指标计算 / failure_analysis 失败归因 /                │
│  benchmark 批量评测 / recommendation 优化建议                  │
├─────────────────────────────────────────────────────────────┤
│  执行层（Sorting Engine）                                      │
│  engine 编排 / planner 路径规划 / strategies 重试与容错 /      │
│  失败注入概率模型（评测真实感的核心）                          │
├─────────────────────────────────────────────────────────────┤
│  智能层（VLA）            │  环境层（Simulation）              │
│  rule_based（默认）       │  SortingEnv（MuJoCo / Mock）       │
│  vlm_rule / smolvla       │  robot / objects / camera          │
│  + 世界模型（风险预判）   │                                    │
├─────────────────────────────────────────────────────────────┤
│  基础设施（Storage SQLite+JSON / utils / config）             │
└─────────────────────────────────────────────────────────────┘
```

**架构上的关键产品决策：**

- **VLA 与仿真都是可插拔的三级降级。** VLA：smolvla → vlm_rule → rule_based；仿真：MuJoCo → MockPhysics；加速：MPS → CPU。这不是技术洁癖，而是产品承诺——"任何环境都能跑出结论"。
- **失败注入放在执行层而非算法层。** 因为产品验证阶段我们不需要真实 CV/VLA 的算力，只需要"统计上真实"的失败分布来驱动评测和归因。这把验证成本降了一个数量级。
- **评测层和决策层严格只读 storage。** 看板不在前端跑重仿真，所有数据先落库再消费。保证了看板秒开、可复现、可审计。

## 五、从"技术 Demo"到"可落地产品"还差什么（思考链路）

这是本产品最有 PM 价值的一节。我们诚实地拆解：一个能在仿真里分拣的 Demo，到真正进产线，中间隔着哪些鸿沟。

### 鸿沟 1：仿真到现实的 Sim2Real Gap
- **现状**：我们用 MuJoCo / Mock 仿真，物理参数是理想化的。
- **差距**：真实产线有光照变化、油污反光、传送带振动、零件粘连。
- **产品对策（已埋点）**：困难难度引入遮挡和相似物，失败注入模型显式建模"光照角度问题""物体意外移动"。下一步需接真实相机数据做 Sim2Real 校准。

### 鸿沟 2：长尾失败的可控性
- **现状**：评测能跑出 5 类失败分布。
- **差距**：产线不能接受"偶尔报废一个显示屏"。需要把易碎件放置失败率压到接近 0，并保证失败时能安全停机。
- **产品对策（已埋点）**：世界模型 `assess_grasp_risk` 在抓取前预判风险；strategies 提供置信度阈值 + 人工介入兜底。这是"可控失败"的产品雏形。

### 鸿沟 3：从"单工位"到"产线集成"
- **现状**：单机械臂、单工作台、3 个料盒。
- **差距**：真实产线要和 MES/上位机/传送带 PLC 联动，要处理节拍、节流、堆料。
- **产品对策**：架构上 storage 已用标准 schema，benchmark 已用 ISO8601 时间戳，为后续对接埋好接口。

### 鸿沟 4：信任与责任边界
- **现状**：失败有归因。
- **差距**：产线决策者要的是"在什么置信度下让 AI 自主、什么情况下必须人工"，这是责任划分问题，不是技术问题。
- **产品对策**：过程指标里的"人工介入率""异常恢复率"，正是为定义这条"信任边界"准备的数据底座。

### 鸿沟 5：成本账
- **现状**：辅助指标已含"平均重试次数""人工介入率"。
- **差距**：要算清单位分拣成本（电力/折旧/人工兜底）vs 传统方案，才能说服 CFO。
- **产品对策**：成本组指标是为这笔账预留的输入，下一版接入真实成本系数即可输出 ROI。

> 这一节的方法论：**我们不假装 Demo 等于产品，而是把每个鸿沟都映射到一个已经在产品里埋好的"观测点"或"降级机制"。** 这就是产品验证系统的价值——它不只告诉你"能做"，还告诉你"还差什么、差距有没有抓手"。

## 六、版本规划

| 版本 | 主题 | 关键能力 | 对应指标目标 | 状态 |
|---|---|---|---|---|
| **v1** | 基线验证 | rule_based VLA + baseline 策略 + Mock 仿真，跑通全链路评测 | 总成功率 ≈ 0.62 | 已交付（种子数据） |
| **v2** | 策略优化 | optimized 策略（更优置信度阈值/重试/异常恢复） | 总成功率 ≈ 0.74 | 已交付（种子数据） |
| **v3** | 世界模型增强 | optimized 策略 + world_model 抓取前风险预判 | 总成功率 ≈ 0.83 | 已交付（种子数据） |
| **v4（规划）** | 多视角融合 | 引入侧视相机融合，主攻感知类失败（遮挡） | 困难难度成功率 +6~8pct | 规划中 |
| **v5（规划）** | 模糊指令优化 | 强化模糊语义解析（"大左小右"类） | 理解类失败 -50% | 规划中 |
| **v6（远期）** | Sim2Real + 真实模型 | 接 SmolVLA 真实推理 + 真实相机校准 | 缩小 Sim2Real Gap | 远期 |

> 版本规划原则：**每一版都由上一版的失败分析驱动，按"高影响低成本"排优先级**，详见 `iteration_plan.md`。v1→v3 已用真实评测数据验证了"失败归因 → 针对性优化 → 成功率提升"的闭环可行，这正是本产品要证明的核心命题。

## 七、小结

本产品的一句话价值主张：**它把"VLA 工业分拣能否落地"这个模糊的技术问题，变成了一个有指标、有归因、有迭代路线、可被决策者读懂的产品命题。** 我们不靠一个漂亮的抓取视频说话，而是靠一套"成功率从 0.62 涨到 0.83、每一步涨幅都有失败归因支撑"的完整证据链说话。这，就是从算法 Demo 到产品验证的本质跨越。
